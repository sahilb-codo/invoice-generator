# Phase 05 — Print and Save as PDF

**Status:** Complete. Committed as `a5eb734`.

Prompt: [05-print-pdf.md](../prompts/05-print-pdf.md)

## Objective

Print only the invoice — as a real business document — through the browser's native print dialog,
which also provides "Save as PDF".

## Features implemented

- **Print / PDF** button in the header calls `window.print()` from the click. No fake download
  button; the PDF is produced by the browser's own "Save as PDF" destination.
- While the dialog is open, the document title becomes `Invoice INV-2026-0042 — Ava Thompson`, so
  "Save as PDF" suggests that file name; the title is restored on `afterprint`.
- **Dedicated print stylesheet** [`src/app/print.css`](../../src/app/print.css):
  - A4 page (`@page { size: A4; margin: 14mm 14mm 16mm }`).
  - Hides header, tabs, editor, toasts and the Next.js dev overlay; only the invoice prints.
  - Prints the invoice even when the mobile **Editor** tab is active.
  - Removes the on-screen card styling (shadow, rounded corners, scroll container, sticky).
  - 9.5 pt document type; `print-color-adjust: exact` keeps the brand band and total highlight.
  - Multi-page: table header repeats (`table-header-group`), rows never split, meta block,
    totals and footer are kept together.
- Preview uses `print:` variants so the desktop document layout (two-column header, unit price
  column) is used on paper regardless of the screen the user prints from.
- Hidden custom fields cannot print: the preview never renders them (`getVisibleCustomFields`).

## Technical decisions

- **Native print only.** Meets "Save as PDF" without a PDF library; users get exactly what the
  browser renders from the print stylesheet.
- **Semantic `data-print` hooks** instead of scattering `print:hidden` on many elements, so the
  print contract is readable in one file.
- **Block flow for all ancestors in print** (`data-print="flow"`, `body`): page wrappers are flex
  containers on screen.
- **No `break-before: avoid` on totals** — see the bug below.

### Bug found and fixed during verification

The first multi-page PDF split the totals: Subtotal + Discount at the bottom of page 2, Tax + Total
Due on page 3. Debugging (computed styles of every ancestor under print media) showed all
ancestors were already block-level; the cause was `break-before: avoid` on the totals combined with
`break-inside: avoid` — with no legal break point left, Chrome broke inside the totals. Removing
`break-before: avoid` fixed it (verified in the regenerated PDF). The flex → block change for
wrappers was kept, as it removes another known Chrome limitation.

## Known issues

- Browser print headers/footers (URL, date) are controlled by the user's print dialog
  ("Headers and footers"), not by the page.
- Only Chrome was tested automatically; Firefox and Safari may paginate slightly differently.
- No server-generated PDF (e.g. as an email attachment) — see Phase 08.
